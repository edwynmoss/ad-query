# Microsoft 365 / Entra check, setup

AD Query can enrich directory results with Microsoft 365 / Entra facts (account
exists/enabled, assigned licenses, last sign-in). It signs in **as the current
user** via the OAuth2 **device-code** flow, delegated, no client secret, no
password stored. On a domain/Entra-joined machine the browser step is silent
(SSO via the user's Primary Refresh Token).

## No app registration required (default)

By default AD Query signs you in through Microsoft's own first-party
**"Microsoft Graph Command Line Tools"** public client (the same app
`Connect-MgGraph` uses). **You don't register anything and you don't type any
GUIDs**, just click **☁ → Sign in** and authenticate as yourself.

Because the enrichment reads *other* users' license/sign-in data, the delegated
scopes (`User.Read.All`, `Directory.Read.All`, optionally `AuditLog.Read.All`)
are admin-consent permissions. The **first** time someone in the tenant signs
in, a Global Admin may need to approve them once (Entra shows a "needs admin
approval" prompt, or an admin grants consent for the app). After that, any
permitted user can sign in with no further setup.

## In the app

1. Click the **☁ (cloud)** button in the toolbar.
2. Click **Sign in**, no input needed. Your default browser opens to the
   Microsoft sign-in page (auth-code + PKCE over a loopback redirect). If you
   already have an Entra session it completes **silently** and returns to the
   app; otherwise you sign in once. With access to more than one tenant, the
   account picker lets you choose which to use.
3. **Headless / locked-down machine?** Use **"Can't use a browser? Sign in with
   a code"** for the device-code fallback (open the URL on another device,
   enter the code).

## Optional: bring your own app registration

Organisations that block the built-in client, or prefer their own app, can
register a **public client** and enter its **Tenant ID** + **Client ID** under
the dialog's **Advanced** section:

1. Entra admin centre → **App registrations** → **New registration** (name e.g. `AD Query`, redirect URI blank).
2. **Authentication** → **Allow public client flows** = **Yes**.
3. **API permissions** → **Microsoft Graph → Delegated**: `User.Read.All`, `Directory.Read.All`, *(optional)* `AuditLog.Read.All` → **Grant admin consent**.
4. Copy the **Application (client) ID** and **Directory (tenant) ID** into the Advanced fields.
4. In **Bulk lookup**, tick **Also check Microsoft 365**, the export then gains
   `365 Account`, `365 Enabled`, `365 Licenses`, and `365 Last sign-in` columns.

## Notes / limits

- **Last sign-in** needs `AuditLog.Read.All` + Entra ID P1; without it that column is blank.
- The token lives only in memory for the session; sign-out clears it.
- This path is validated against a real tenant, it cannot be exercised on a
  non-domain dev machine. The engine's parsing/flow logic is unit-tested
  (`app/backend/m365`).
